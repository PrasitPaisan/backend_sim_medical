# backend-sim

NestJS backend for the pharmacy dispensing automation console. Receives prescriptions from a hospital HIS, tracks them through a fixed pipeline of dispensing stations, and dispatches them to physical dispensing machines (RB1500, NZP360) over SOAP/XML.

Raw `pg` (no ORM) — the database schema lives in Postgres itself, not in migration files generated by a framework.

## Machine integration

Every call that talks to a real dispensing machine follows the same shape: a `.../preview` endpoint builds and returns the exact SOAP XML a real send would transmit (by reusing the same private builder the real send uses, so preview can never drift from what actually goes out over the wire), and a paired mutating/query endpoint fires the real call. See `src/machine/` (machine-only calls with no database read/write) and `src/prescriptions/prescriptions.service.ts` (prescription send flows that also bind/release baskets).

**RB1500** — `SendMedicine`, `SendPrescription`, `QueryMachineState`, `QueryBasket`, `QueryBasketPosition`, `QueryInventory`, `QueryReadyPrescription`, `QueryCOBOTTask`, `UpdateCOBOTTask`, `UpdateReadyPrescriptionState`, `ExecEliminatePrescription` — all confirmed against a real machine (SOAP 1.2 envelope, folded-action `Content-Type`, no separate `SOAPAction` header).

**NZP360** — `SendMedicine`, `SendDeptInfo`, `SendPrescription`, `QueryInventory` confirmed live; `QueryMachineState` and `QueryPackagedInfo`/`UpdatePackagedInfo` are rejected by this dev unit with an "unrecognized operation" SOAP fault (field-level shapes are built to the ATDPS integration doc's spec regardless, in case a different machine build accepts them). NZP360 calls carry a `Token` header (`MACHINE_TOKEN_NZP360` in `.env`, currently a placeholder pending the login endpoint's spec). The **Nursing Interface** (`Nursing`/`NursingCode`, ATDPS doc §3.4 — looks up a drug bag's medicine lines / nursing codes by its 2D code) has backend scaffolding (`/machine/nursing-nzp360`, `/machine/nursing-code-nzp360`, plus `/preview` counterparts) but is not yet confirmed against the real machine.

## Prerequisites

- Node.js + npm
- A running PostgreSQL instance (developed against 18.x, but no exotic features are used — anything reasonably recent should work)

## Setup

1. Install dependencies:
   ```bash
   npm install
   ```

2. Copy the env template and fill it in:
   ```bash
   cp .env.example .env
   ```
   - `DB_*` — point at your Postgres instance/database.
   - `MACHINE_PATH_RB1500` / `MACHINE_PATH_NZP360` — the physical dispensing machines' SOAP endpoints. Leaving these unset does not crash the server, but any call that sends to a machine (medicines, prescriptions, department sync, machine status) will report failure.
   - `MACHINE_TOKEN_NZP360` — auth token NZP360 requires on every call (unlike RB1500). Leave blank until the login endpoint that issues it is documented; NZP360 calls will still fire without it, just without the header.
   - `PORT` — the port this API listens on (the frontend's `VITE_API_BASE_URL` must match this).

3. **Database schema.**

   **Fresh/empty database (e.g. a new Supabase project):** run `schema.sql` once — it creates every table this app uses (`prescription_header`, `prescription_detail`, `medicine_dictionary`, `basket`, `department_dictionary`, plus a few reserved-for-later tables) and seeds the basket pool, in one shot:
   ```bash
   psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME -f schema.sql
   ```
   (On Supabase: paste its contents into the SQL Editor and run it instead.)

   **Existing database that predates `schema.sql`** (already has `prescription_header`/`prescription_detail`/`medicine_dictionary`/`basket`): apply these three incremental files **in this order** instead:
   ```bash
   psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME -f create-department-dictionary.sql      # creates department_dictionary
   psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME -f add-nzp360-prescription-columns.sql    # adds NZP360-only columns to prescription_header/prescription_detail
   psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME -f seed-baskets.sql                        # seeds the basket pool (BASKET-01..20) — safe to re-run
   ```

4. Run it:
   ```bash
   npm run start:dev   # watch mode
   ```

## Scripts

- `npm run start:dev` — dev server with watch/reload

- `npm run test` — unit tests (`*.spec.ts` under `src`)
- `npm run test:e2e` — e2e tests
